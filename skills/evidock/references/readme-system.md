# README System v0.6

A strong README is a Front Door, not a code dump.

Recommended order: identity + one-line outcome; real demo/proof; why/for whom; quick start; core usage; evidence-backed capabilities; configuration/limitations; architecture when useful; contributing/support/license.

Lead with product value, not framework trivia. Put strongest proof near the fold. Keep first successful result short. Never fabricate badges, metrics, adoption, benchmarks, compatibility, or testimonials. If capability is incomplete, label it accurately.
