# Proof Mode v0.6

Proof Mode turns an important claim into the smallest safe experiment that can strengthen or refute it.

Use it when a core advertised workflow can be exercised safely, installation/runtime viability changes Launch Status, static evidence is ambiguous, or a consequential claim can be checked without destructive side effects.

Prefer: static/config evidence → project-defined tests → small isolated runtime experiment → full documented quick start. Stop as soon as evidence is sufficient.

Record id, optional claim_id, scope, action, result, observations, and limitations. Results: PASS / FAIL / INCONCLUSIVE / SKIPPED.

**VERIFIED IN SANDBOX ≠ VERIFIED EVERYWHERE.** Never generalize one successful environment into cross-platform compatibility, production readiness, performance, security, or reliability claims.

Do not deploy/publish, use real credentials, contact production unnecessarily, make purchases, mutate external data, run suspicious binaries, or run migrations against non-disposable databases.
